# ADR-0009：v0.1 执行与真实厨房验收基线

## 决策

v0.1 本地平台采用 Rust Axum 控制面与独立 Python OCI Worker。控制面默认仅监听 loopback，使用文件 CAS 与 SQLite WAL；Worker 只通过版本化 Job/Result Manifest 和内容 Digest 交换数据，不共享隐式路径。

首个 L3 案例采用带浮动基座的 H1 与 Robotiq 2F-85。任务固定为 H1 行走 1–2 米后完成“打开抽屉、抓杯、将杯子放入并释放、关闭抽屉”。固定初始状态必须连续 5 次全部通过。

物理任务证据、3DGS 视觉壳证据和视觉壳开启前后的物理不变性证据分别生成；只有三者均通过，才认定真实厨房案例完成。私有、非商业或相机覆盖不合格的厨房只能作为受限证据或负例。

## 后果

- 未获得真实 GPU 运行、合法厨房源、相机覆盖或成功 Witness 时，相应阶段保持未验收。
- Mock 仅用于普通 CI，不能替代 GPU、浏览器、MuJoCo 原生加载或 L3 行为证据。
- 法律审查完成前允许在功能分支开发和内部验证，但禁止公开发布或合并发布分支。
